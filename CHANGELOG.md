# Changelog

The Uorqui social platform uses [Semantic Versioning](https://semver.org/) for its application workspace manifests. The suffix `-beta.N` marks a **pre-release**, not a stable or generally available product.

## [Unreleased]

All subsequent changes must increase the version in all three npm manifests and update both changelogs. See [release policy](docs/en/versions.md).

## [0.1.0-beta.32] — 2026-11-10

- **Cloudflare Free rate limit activated in production:** one zone-level `http_ratelimit` WAF rule protects `/api/*` from bursts of over **120 requests per 10 seconds per source IP and Cloudflare colo**. Blocks for **10 seconds**, then permits new requests. Uses the Free plan's available rule; no subscription upgrade needed.
- **Preserves chat availability:** excludes `/api/v1/dm/events`, `/api/v1/communities/events` (SSE) and public `/api/v1/status`. Health endpoints are outside `/api/*`. No application request contracts, R2 bucket rules, or database tables were changed.
- **Operations and rollback:** complete rule expression, Cloudflare ruleset/rule IDs, diagnostics, shared-IP considerations and Cloudflare-side rollback are documented in [Cloudflare rate limiting](docs/en/cloudflare-rate-limiting.md). A Git code rollback does not disable an active Cloudflare rule.
- **Scope:** mitigates abnormal API bursts but does **not** eliminate upstream provider HTTP 429 responses caused by Render limits.

## [0.1.0-beta.31] — 2026-11-10

- **HTTP 429 resilience:** login boot now requests public status, readiness, then session sequentially instead of firing concurrent probes. For rate-limited responses, it honors a bounded `Retry-After` with a 30–180 second backoff and shows a clear in-app message instead of an endless loading screen.
- **Less upstream load:** the Cloudflare Worker briefly caches only successful public `/api/v1/status` and `/health/ready` replies for 15 seconds per edge location. Private endpoints such as `/api/v1/me`, messages, and email are never cached. Non-200 and personalized responses are not cached.
- **Diagnostics:** forwarded upstream HTTP 429 responses include `x-uorqui-upstream-429: 1` and public probe responses include `x-uorqui-probe-cache: HIT|MISS`. This distinguishes an upstream limit from an edge-generated block in the browser Network panel.
- **Infrastructure note:** HTTP 429 is not generated by the Fastify application handlers or the Worker proxy; the upstream deployment/provider may throttle incoming traffic (especially lower-tier Render instances). These changes reduce retries and load, but cannot override a provider-level limit. No database migration.
- **Checks:** frontend backoff and cache/bootstrap regression tests are included in CI. Validate on Cloudflare and Render after publishing.

## [0.1.0-beta.20] — 2026-11-09

## [0.1.0-beta.18] — 2026-11-09

- **One app instance per device category:** one active desktop document and one active mobile/PWA document per authenticated account, including different browsers. A second tab is paused instead of signing out; **Use this tab** explicitly takes control of that category. The prior owner is suspended (chat/SSE/media cleanup on unmount) without revoking its Better Auth login.
- **Atomic server lease:** PostgreSQL migration `0043_app_instance_leases.sql` adds one row per account + category. `POST /api/v1/instances/claim` atomically acquires/renews or returns `409 INSTANCE_IN_USE`; only explicit `takeover:true` may displace a live owner. Expired leases (60 s) can be recovered automatically; `/release` only releases the requesting instance. Write routes require a valid session and exact write origin. Missing migration temporarily permits normal operation during staggered deployment instead of locking out users; enable enforcement by applying migration before treating the limit as live.
- **Fast handover:** BroadcastChannel blocks the previous tab instantly within one origin. A new SSE `instance-lease` event notifies other browsers when an explicit takeover occurs; a 15-second heartbeat is the fallback. Transient network failures retry; repeated failures temporarily suspend the workspace without logging out. Mobile is detected from user agent (including desktop-mode iPadOS), independent of window width. An instance is a *document*, not a login session; this limits the app UI, not direct access to authenticated APIs by a malicious client.
- **Scope/testing:** integration tests cover user/session separation, independent desktop/mobile limits, origin validation, takeover, stale release, and expiry using disposable PostgreSQL. Re-test duplicated browser tabs, browser restart, iOS/Android PWA, desktop and mobile concurrently, voice call teardown and connectivity loss. Requires additive SQL migration; no existing session revocation or push permission changes.
