# Como contribuir com o Uorqui

[Português (Brasil)](CONTRIBUTING.pt-BR.md) · [English](CONTRIBUTING.md)

Obrigado pelo interesse em contribuir com o Uorqui.

> **Situação atual:** pré-MVP. Já existe uma estrutura inicial de interface/API para desenvolvimento local, mas a rede social, o banco e o deploy ainda não estão prontos. Veja [Primeiros passos](docs/pt-BR/primeiros-passos.md).

## Antes de começar

- Leia a [visão](docs/pt-BR/visao.md), os [requisitos](docs/pt-BR/produto.md), o [roadmap](docs/pt-BR/roadmap.md) e o [código de conduta](CODE_OF_CONDUCT.pt-BR.md).
- Abra uma issue ou discussão no GitHub antes de implementar recursos grandes ou mudanças arquiteturais. Tecnologias propostas ainda não são necessariamente aprovadas.
- Comece por mudanças pequenas: esclarecer requisitos, corrigir links, preparar testes quando existir código ou melhorar acessibilidade e traduções.
- Não propor grupos tradicionais no mensageiro; comunicação coletiva acontece em canais de comunidades.

## Padrões de documentação

- O inglês é o idioma principal da documentação do GitHub; o **português brasileiro é mantido em paralelo**.
- Alterações de comportamento ou arquitetura devem atualizar os dois idiomas no mesmo pull request.
- Diferencie decisões aprovadas, propostas e hipóteses.
- Não publique estratégia comercial, preços não divulgados, pesquisa interna, projeções financeiras, credenciais ou dados de usuários.

## Pull requests

1. Faça um fork e crie uma branch descritiva.
2. Envie uma mudança focada, explicando **por que** ela é necessária.
3. Vincule a issue correspondente quando houver e descreva os fluxos impactados.
4. Atualize a documentação relacionada nos dois idiomas.
5. Quando houver código e comandos de teste documentados, execute as verificações e informe os resultados.
6. Abra um pull request para revisão. Ajustes podem ser solicitados antes do merge.

Nunca envie segredos, tokens, dados de produção, código proprietário de terceiros ou mídias sem licenças adequadas.

## Qualidade esperada

Acessibilidade, privacidade, boa experiência mobile, mensagens em tempo real confiáveis e limites de recursos de voz/vídeo são importantes desde o início. Alterações de permissões ou conteúdo privado exigem autorização no servidor e revisão de segurança.

## Licença

Ao contribuir, você concorda que suas contribuições sejam disponibilizadas sob a [licença MIT](LICENSE), salvo acordo escrito explícito em contrário. Confirme que possui direito de contribuir com o material.

Para vulnerabilidades, **não publique detalhes de exploração em issues públicas**; consulte [SECURITY.pt-BR.md](SECURITY.pt-BR.md).
